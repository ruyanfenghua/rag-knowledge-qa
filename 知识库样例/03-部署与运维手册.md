部署与运维手册

适用版本 V4.x，部署方式为私有化或混合云。

一、服务端服务器配置要求

这一节说的是部署系统的服务器，不是客服办公用的电脑。客服电脑的要求见产品功能说明第六节。

50 坐席以下用单机部署，8 核处理器，16G 内存，500G 固态硬盘。50 至 200 坐席，应用与数据库分离，16 核 32G，1T 固态。200 坐席以上用双机热备，32 核两台，64G 内存，2T 固态。

操作系统用 CentOS 7.9 或 Ubuntu 20.04 及以上，内核版本 3.10 以上。

二、端口清单

80 端口走 HTTP，用于跳转 HTTPS，443 是 HTTPS 主入口，这两个对外开放。3306 给 MySQL，6379 给 Redis，8080 给应用服务，9090 给监控指标，这四个只在内网访问。

防火墙只需放行 80 和 443。

三、部署步骤

1. 安装基础依赖，JDK 17、MySQL 8.0、Redis 6.2、Nginx 1.20。
2. 导入初始化 SQL，创建业务库与只读账号。
3. 修改 application-prod.yml，填写数据库地址、Redis 地址和文件存储路径。
4. 执行 bin 目录下的启动脚本，日志输出到 logs 目录的 app.log。
5. 配置 Nginx 反向代理，证书放到 ssl 目录。
6. 访问 health 路径，确认返回状态为 UP。

四、备份策略

数据库每日凌晨 2 点做全量备份，保留 30 天；增量备份每小时一次，保留 7 天。附件存储每周同步到对象存储。每季度做一次恢复演练，演练记录归档。

备份文件必须存放在与生产不同的物理机器上。同一台机器上的备份不算备份。

五、常见故障处理

故障码 5001：数据库连接池耗尽

现象是页面报错，日志出现 Connection is not available。处理时先查是否有慢查询，再看连接池配置。默认最大连接 50，坐席数超过 100 时建议调到 120。

故障码 5002：Redis 连接超时

现象是登录缓慢，会话状态丢失。处理时检查 Redis 内存使用率，超过 80% 会触发淘汰。执行 redis-cli info memory 可以查看当前用量。

故障码 5003：磁盘空间不足

现象是消息发送失败，图片上传报错。处理时清理 data 目录下 logs 里 7 天前的日志，检查备份目录是不是堆积了。

服务启动不了

按顺序排查四件事：进程是否残留，用 ps 查 java 进程；端口是否被占用，用 netstat 查 8080；配置文件是否有语法错误；日志最后 200 行有没有异常堆栈。

六、升级流程

1. 升级前做一次完整备份。
2. 停止应用，保留旧版本目录。
3. 解压升级包，执行数据库变更脚本。
4. 启动新版本，验证 health 状态和核心页面。
5. 观察 30 分钟，无异常再清理旧版本。

升级窗口建议安排在业务低峰期，通常是晚上 22 点之后。回滚方式是切回旧目录并恢复数据库备份，回滚时间约 20 分钟。
